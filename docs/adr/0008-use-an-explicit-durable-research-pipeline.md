# Usar una pipeline de investigación explícita y durable

El MVP implementará una pipeline propia con Vercel Workflow SDK y AI SDK Core, proveedores intercambiables de inferencia, búsqueda y OCR, y reglas deterministas para cobertura e índice. Eve no será dependencia porque su runtime de agentes beta aporta autonomía innecesaria a un proceso cerrado; JEV tampoco será el motor porque no busca, procesa imágenes, cita ni redacta y no cubre por sí solo la pipeline. Vercel AI Gateway será la puerta de enlace inicial de inferencia y su herramienta `gateway.tools.exaSearch()` será la ruta primaria de búsqueda, ambos encapsulados para poder sustituirlos sin cambiar el dominio ni el formato permanente de los informes. Mientras AI Gateway exija verificación de cuenta incluso para sus modelos gratuitos o rechace la herramienta por cuota o indisponibilidad, el adaptador podrá recurrir a la `EXA_API_KEY` directa ya configurada, bajo el mismo presupuesto y las mismas validaciones; esto no habilita proveedores pagos ni convierte snippets en evidencia. La inferencia usará un pool ordenado de modelos gratuitos, cada uno aprobado previamente mediante el corpus multilingüe, y podrá hacer fallback solamente entre integrantes de ese pool. No habrá fallback pago ni recarga automática. Los límites de tasa, periodo, crédito y disponibilidad impuestos por AI Gateway o sus proveedores prevalecerán sobre los cupos internos configurables. La búsqueda tendrá también un presupuesto duro y no continuará cuando se agote el crédito disponible. Si no existe un modelo gratuito aprobado o capacidad de búsqueda disponible, la investigación terminará parcial o fallida antes de generar un cargo.
